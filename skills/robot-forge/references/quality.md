# 质量与评审 v2.0

> 目的：让“完成”不取决于模型的自信心，而取决于**可复现的证据 + 可复算的分数**。
> 机器分由 `rf_audit` 算（六维、规则映射），人评分由盲审给（判断、攻击面、可维护性）。两者都过才算发布。
> 契约见 `spec.md`；流程见 `workflow.md`；测试见 `testing.md`。

---

## 1. 六维评分（100 分，机器算）

| 维度 | 权重 | 覆盖 | 扣分来源（示例） |
|---|---:|---|---|
| 买得到 buyable | 15 | BOM 真实、价格、替代料、供应链 | S2/S3/S7/S14/D9/CST-09/CST-13 |
| 造得出 buildable | 20 | 结构、装配、CAD、机械、清单 | 其余结构/文档外错误（S4/S5/S6/S8/S9/S10/S12…） |
| 跑得起来 runnable | 25 | 固件/软件/仿真能跑、测试、协议 | firmware/software/sim 文件问题、CST-08 |
| 说得清 explainable | 15 | 文档、链接、生成块、可读性 | D7/D8 或 docs/README/CHANGELOG/LICENSE 问题 |
| 证得了 evidenced | 15 | must 覆盖 | 15 × 覆盖率（measured/manual 才算） |
| 安全与许可 safety | 10 | 九类旗标、密钥、许可 | S11/CST-07/CST-10/CST-11 |

**算分规则**（与 `api._scorecard` 一致）：
- 每维起始满分；该维每有 1 个 error 扣 6，1 个 warning 扣 1，最低 0；
- `D4`（证据缺失）不计入 buildable，避免与 evidenced 双罚；
- evidenced = 15 × must 覆盖率 / 100；
- 总分四舍五入；`rf_audit` 输出六维明细。

**判定：**

```text
release：0 error + must 覆盖 100% + 总分 ≥85
beta   ：0 error，但覆盖 <100% 或分数 70–84
blocked：有 error，或覆盖 <100% 且未标 Beta，或分数 <70
```

**评分不是目的**：先找 blocker，再谈分数；风格偏好最多 minor，不算 blocker。

## 2. 盲审协议（强制）

1. **盲审**：不看实现者解释，只看仓库 + `forge/` + 命令输出；要改就改交付物。
2. **新鲜证据**：评审者自己重跑关键命令，不引用实现者输出；干净 shell/目录，必要时复制项目到新目录。
3. **三副眼镜**（依次，不合并）：
   - 逻辑：需求→实现→测试闭环？边界/异常/超时/断网？
   - 攻击面：误操作、儿童/宠物、过热、堵转、短路、隐私、密钥、供应链；
   - 可维护性：陌生人能改？参数集中？文档与代码同步？升级会不会砖？
4. **发现物编号** `QF-<轮次>-<序号>`，含严重度、文件:行、问题、**必须怎么修**、证据。
5. **不谈判**：评审者不改代码；修复由实现者做，评审者复评。
6. **3 轮预算**：同一问题 3 轮未闭 → 升级为设计问题（需求/约束冲突），停下让用户选。
7. **不刷风格分**：命名/排版最多 minor；不要用 50 条 minor 淹没 1 条 blocker。

### 发现物格式

```text
QF-1-03 | blocker | firmware/src/motion.cpp:88
问题：堵转检测只在 loop 里判断，delay(200) 期间不生效，手按住 5s 不会断电。
必须修：把检测放进定时器/中断，或把 delay 换成非阻塞状态机；补一条 native 单测模拟堵转 5s。
证据：pio test -e native 目前 0 个堵转用例；manual 步骤无法证明保护生效。
```

### 评审包与结论

`rf_review` 生成 `forge/review-packet.md/json`（复现命令、trace、最近证据、机器发现、模板、哈希）。评审者按固定结构回传：

```markdown
# 评审 QF-<n>
结论：PASS / CONDITIONAL / FAIL
总分：xx/100
Blocker：n 条（逐条 QF 编号）
Major：n 条
Minor：n 条（可合并）
复跑记录：<命令> → exit <n>（关键输出）
未覆盖风险：<无法在本机验证的项>
下一步：<最多 3 条>
```

由未参与实现的评审者给出结论，Lead 用 `review --verdict ... --score ... --reviewer ... --findings ...` 写入 `forge/review.json`；源码或盲审包一变即失效。`rf_audit` 只有在结论为 pass、无未解决 blocker、score>=70、且与当前构建一致时才判 release。

## 3. 假绿封堵（评审第一优先级）

| 假绿类型 | 识别方法 | 处理 |
|---|---|---|
| 只测 mock | 搜 mock/fake，确认是否有真实路径测试 | 至少 1 条集成路径；否则标 simulated |
| 断言写死 | 只断言常量/自身构造值 | 断言行为/输出/状态变化 |
| 删断言变绿 | 对比改动前后测试数量与断言 | 恢复；删除需 decisions 记录理由 |
| 空跑命令 | verify 里 echo/true/sleep/exit 0 | 删除或换真实命令；CST-08 拦 |
| 跳过未声明 | skipped/xfail 但文档说通过 | 显式列原因；required 不得跳过 |
| 编译冒充测试 | 只 build 不 test | 必须有 test；build 只是前置 |
| 仿真冒充实测 | simulated 写成“已实测” | D8 抓；改 simulated + 待实物 |
| 环境特供 | 绝对路径/私有服务 | 干净目录复跑；锁依赖 |
| 指标偷换 | 需求 1.5m，只测 30cm | 按原值验收；改需求需用户同意 |
| 图片占位 | 示意图/渲染图称实拍 | 标注“渲染图”，实拍另附 |

**红-绿验证（强烈建议）**：临时改坏关键实现（如堵转阈值改 999），对应测试必须失败；恢复后必须通过。测试不红，说明没在测东西。

## 4. 分域评审清单

### 4.1 需求与范围
- [ ] must ≤6 条，每条可观察/可验收；
- [ ] must_not 明确（隐私、联网、噪音、动作范围）；
- [ ] nice 不阻塞交付；
- [ ] 需求无冲突；冲突有 decisions 取舍；
- [ ] 没把“实现方式”写成“用户需求”。

### 4.2 BOM 与采购
- [ ] 型号可搜到；关键件有替代料；
- [ ] 数量含备件（≥10%）；
- [ ] 单价含税口径一致；运费计入；
- [ ] 电源/线材/端子/紧固件没漏；
- [ ] 工具列全（打印/焊接/压接/烧录）；
- [ ] 交期风险有提示（进口/缺货）。

### 4.3 结构与 CAD
- [ ] 参数化脚本能从零导出；
- [ ] 关键配合有公差（M3/热熔/轴承/舵机）；
- [ ] 打印方向合理、少支撑；
- [ ] 装配可达（螺丝刀能伸进去）；
- [ ] 重心/稳定性/防倾倒；
- [ ] 运动包络无干涉（含线材）；
- [ ] 边角/夹点对儿童宠物友好。

### 4.4 电子与接线
- [ ] 引脚不冲突、不占保留脚；
- [ ] I2C 地址唯一；总线上拉；
- [ ] 电源分轨、共地、峰值余量 ≥30%；
- [ ] 舵机/电机独立供电 + 母线电容；
- [ ] 急停/断电/反接保护；
- [ ] 接线表与固件 config 一致；
- [ ] 上电顺序与首次上电步骤明确。

### 4.5 固件
- [ ] 能编译（锁版本/板型）；
- [ ] 看门狗、超时、限位、堵转、欠压保护；
- [ ] 协议解析有长度/校验/越界保护；
- [ ] 不阻塞（delay 不超 10ms，长延时用状态机）；
- [ ] 失联自动安全状态；
- [ ] 无密钥/无调试后门；
- [ ] 单测覆盖协议与保护逻辑。

### 4.6 主机软件
- [ ] `--mock` 可启动，无需硬件；
- [ ] 串口断线重连；协议边界用例；
- [ ] 配置集中，密钥走环境变量；
- [ ] 默认隐私（不录音/不上传/有指示）；
- [ ] 依赖锁版本；Python 版本写清；
- [ ] 单测不依赖网络与硬件。

### 4.7 仿真
- [ ] 一条命令给数值结论（不是只开 GUI）；
- [ ] 场景参数与 CAD/manifest 一致；
- [ ] 明确“不模拟什么”；
- [ ] 结果用于设计决策（写进 decisions）。

### 4.8 文档
- [ ] README 首屏能看懂“是什么/多少钱/多久/怎么开始”；
- [ ] 3 分钟上手命令可复制；
- [ ] 每步“做完应该看到什么”；
- [ ] 故障排查 ≥8 条，症状级；
- [ ] 安全与隐私按触发项写；
- [ ] 生成块最新；链接可达；
- [ ] 无上游残留名/示例引脚；
- [ ] 中文为主，术语有解释。

### 4.9 证据与发布
- [ ] 每条 must 有 measured/manual；
- [ ] 证据含命令、退出码、产物；
- [ ] manual 有“谁、何时、怎么做、看到什么”；
- [ ] 未验证项逐条列，不藏正文；
- [ ] audit 0 error；覆盖 100% 或 Beta 标注；
- [ ] trace/review-packet 存在且最新；
- [ ] CHANGELOG/LICENSE/.gitignore 齐全；
- [ ] 依赖许可兼容；无 GPL 污染（闭源时）。

## 5. 安全评审（按触发项）

| 触发 | 必查 |
|---|---|
| 锂电池 | 保护板、保险丝、阻燃外壳、过放/过流/过温、充电有人、鼓包停用 |
| 市电 220V | **零基础禁止 DIY**；成品电源/智能插座；断电操作；接地/漏保 |
| 运动部件 | 限位、堵转保护、急停、夹点、儿童/宠物、断电自由落体 |
| 激光 | 人眼安全等级、勿直视、儿童不可及 |
| 加热 | 保险丝、温控、阻燃材料、无人值守禁止 |
| 摄像头/麦克风 | 指示灯、物理断电、默认本地、隐私政策 |
| 网络 | 默认密码修改、OTA 签名、端口最小暴露、密钥不入库 |
| 儿童/户外/医疗 | 小零件/监护/IP 等级/非医疗器械声明 |

**安全章节不能只写“注意安全”**：每条要写“什么危险 → 什么后果 → 怎么避免 → 出事怎么处理”。

## 6. 评审者反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 橡皮图章 | 假绿流入用户 | 至少重跑 3 条关键命令 |
| 风格洪水 | 掩盖 blocker | 风格问题合并 1 条 minor |
| 直接改代码 | 失去独立性 | 只报问题与修法 |
| 与实现者谈判 | 结论被稀释 | 按契约判，不按态度判 |
| 审自己 | 利益冲突 | 换人或脚本复跑 |
| 要求完美 | 永远交付不了 | 区分 blocker/major/minor；85 可发 |
| 忽略“无法验证” | 把待验证当通过 | 标未验证 + 步骤；不算通过也不拦死 |

## 7. 发布判定

```text
可以发布：audit 0 error；覆盖 100%；总分 ≥85；盲审无 blocker；安全/许可通过
可发布 Beta：audit 0 error；覆盖 <100% 或 70–84；docs/09 未验证清单完整；盲审无 blocker
不可发布：任何 error；任何 blocker；假绿；许可冲突；安全章节缺失
```

**Beta 的诚实要求**：README 顶部写“Beta：以下功能待实物验证”；docs/09 的 unverified-list 逐条给验证步骤与预计时间；不得用“完成/成品/已验证”描述未验证部分。安全相关 must（急停、限位、电池保护）不允许 Beta 放行。

## 8. 快速自检（提交前 5 分钟）

```bash
python tools/forge.py design
python tools/forge.py check --deep
python tools/forge.py verify
python tools/forge.py trace --write
python tools/forge.py review --write
python tools/forge.py audit
git status --short
grep -rn "TODO\|待定\|占位" --include="*.md" --include="*.py" . | head
```

再看三件事：
1. 把 README 给完全不懂的人读，他能否说出“买什么、怎么装、怎么跑”；
2. 把 docs/09 每条结论对应到命令/记录，找不到就是没证据；
3. 改掉任意关键参数（引脚/角度/电流），`render` + `check` 能否发现漏改。
