# 验证报告

## 结论

本模板刚生成时**没有任何实测证据**：下面的需求表会显示「未验证」，这是正常的起点，不是失败。发布前必须把每条 must 需求跑出证据。

验证分四态：

| 状态 | 含义 | 怎么产生 |
|---|---|---|
| ✅ measured | 命令真跑过，退出码 0 | `python tools/forge.py verify` |
| 🟡 manual | 人按步骤确认过 | `python tools/forge.py evidence --req ... --level manual --note "谁怎么确认的"` |
| ⚪ simulated | 只在仿真/核算里通过 | 同上，`--level simulated` |
| ⛔ 未验证 | 还没有证据 | 初始状态 |

**只有 measured 能证明「实物跑过」；simulated 只能证明「模型算过」；manual 必须写清谁、怎么确认。**

## 复现

```bash
# 1. 文档与 YAML 一致
python tools/forge.py render --check

# 2. 结构与物理核算
python tools/forge.py check

# 3. 能自动跑的全跑（没装工具的命令会跳过，不算失败）
python tools/forge.py verify

# 4. 需求追踪矩阵（must 覆盖率）
python tools/forge.py trace --write

# 5. 生成可复现盲审包
python tools/forge.py review

# 6. 六维分与发布判定
python tools/forge.py audit

# 7. 只有 release/beta 才能打包
python tools/forge.py package
```

真机步骤：

1. 按 `docs/02` 装配并通过检查点 1-6。
2. 按 `docs/03` 接线并完成上电顺序。
3. 按 `docs/04` 烧录固件，确认 `PING` 有回复。
4. 按 `docs/05` 运行主机软件。
5. 对 REQ-004/005/006 逐条做手工测试，并把结果登记为 manual 证据。

## 记录手工证据的例子

```bash
python tools/forge.py evidence \
  --req REQ-004 \
  --level manual \
  --claim "纸板在 30cm 处触发停车，三次均停" \
  --note "2026-11-11 张三，室内瓷砖，车速 0.2m/s，三次"
```

手工证据也要可复核：写清日期、操作人、环境、车速、重复次数；不要只写「测试通过」。

## 已知限制

- 没有编码器：速度开环，电量下降后实际速度变慢。
- 超声只测正前方，侧面与玻璃不可靠。
- 续航数据来自核算，实测受地面、温度、载重影响。
