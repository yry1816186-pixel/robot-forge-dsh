# 设计决策记录

> 只追加，不改写。每条决策都写清「为什么不选另一个」，避免以后反复讨论。
> 格式：编号、日期、状态、背景、决定、代价、被否方案。

## DR-0001 用 ESP32-S3 而不是树莓派

- 日期：{{DATE}}
- 状态：已采纳
- 背景：需要电机 PWM、超声计时、IMU、OLED，还要留 USB 串口给主机。
- 决定：ESP32-S3 开发板做实时层，主机 Python 做交互层。
- 代价：主机不开时只有本地避障与待机；不能跑视觉。
- 被否：树莓派 Zero 2W 能跑完整 Python，但 GPIO 实时性差、价格高、供电复杂，且零基础用户更容易把系统搞坏。

## DR-0002 买 2WD 底盘套件，不自制结构件

- 日期：{{DATE}}
- 状态：已采纳
- 背景：目标是让零基础用户两个周末做出来，不是展示 CAD 能力。
- 决定：结构全部用亚克力底盘套件 + 铜柱，项目里不做 3D 打印件。
- 代价：外形普通，尺寸受套件限制；换底盘要重新核对孔位。
- 被否：自制打印底盘需要打印机、会引入公差与装配风险，且本版本没有结构设计收益。

## DR-0003 不装编码器，速度开环

- 日期：{{DATE}}
- 状态：已采纳
- 背景：TT 电机自带编码器盘，但读取需要另一颗 MCU 或占用大量中断。
- 决定：只用 IMU 修方向，不修速度；速度命令按占空比标定。
- 代价：电池电压下降后实际速度会变慢；直线长时间仍会漂。
- 被否：加编码器会让接线、固件和成本都上一个台阶，违背「两个周末」目标。

## DR-0004 协议用文本而不是二进制

- 日期：{{DATE}}
- 状态：已采纳
- 背景：用户会用串口助手观察，出问题要能肉眼看懂。
- 决定：主机发 `V <lin_mm_s> <ang_mrad_s>` / `S` / `PING`，固件回 `T ...` / `OK` / `ERR <code>`。
- 代价：带宽比二进制大，115200 下仍足够 50 Hz；解析要防超长行。
- 被否：二进制帧更紧凑，但排障门槛高，不符合零基础定位。

## DR-0005 避障放在固件，不放在主机

- 日期：{{DATE}}
- 状态：已采纳
- 背景：USB 断线、主机休眠、程序崩溃都可能发生，安全规则不能依赖主机。
- 决定：固件每 60 ms 测距，连续 3 次小于 300 mm 强制停车；主机只做提示与恢复。
- 代价：固件复杂一点；阈值改起来要重新烧录。
- 被否：纯主机避障实现简单，但主机一挂就失效。

## DR-0006 电池用成品 2S 组，不用升压宝

- 日期：{{DATE}}
- 状态：已采纳
- 背景：TT 电机与驱动在 6V 左右效率最好；5V 充电宝带不动电机峰值。
- 决定：2S 18650 成品电池组（带保护板）+ 6V/5V 两级降压。
- 代价：需要平衡充，多一个充电器；电池安全要求写进 docs/07。
- 被否：单节 3.7V 升 6V 电流太大；充电宝 5V 直供会掉压重启。

## DR-0007 默认不联网

- 日期：{{DATE}}
- 状态：已采纳
- 背景：用户明确不做 Wi-Fi 遥控；联网会引入配网、延迟与隐私问题。
- 决定：只走 USB 串口；固件不包含 Wi-Fi 初始化和任何云调用。
- 代价：不能手机遥控，不能远程看状态。
- 被否：Wi-Fi 遥控需要配网与鉴权，超出两个周末的范围。
