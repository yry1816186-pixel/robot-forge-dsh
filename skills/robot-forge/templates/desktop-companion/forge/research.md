# 调研记录

写这份记录的目的不是显得专业，而是让每个选型都有出处。以下链接在写这份文档时可用；如果失效，搜项目名即可。

## 同类项目

| 项目 | 规模/状态 | 对我们有用的结论 |
|---|---|---|
| xiaozhi-esp32（78/xiaozhi-esp32） | 3.3 万星，MIT，持续更新 | 语音链路已经有成熟实现。我们的固件只做最小音频搬运，复杂对话可以后期接它的协议，不重造轮子 |
| LeRobot / SO-ARM100（huggingface/lerobot、TheRobotStudio/SO-ARM100） | 2.8 万星，机械臂套件约 ¥680 单臂 | 机械臂蓝本的物料与装配方式直接参考它；舵机选型与电源冗余按它的做法 |

| Open Duck Mini（apirrone/Open_Duck_Mini） | 4.7 千星，但无正式 release | 双足开源项目普遍难复现；我们不在 v1 做双足 |
| K-Scale（kscalelabs/kbot） | 2025 年停止运营，全额退款 | 自研人形成本失控的典型案例；默认方案禁止出现自研人形 |
| Vector 停服 | 云端服务停止后机器人变砖 | 任何云能力都必须有本地降级，否则不纳入 must 需求 |

## 关键结论

1. **不重造安全关键固件**：语音、飞控、机械臂都有成熟栈。v1 只做「粘合层 + 表情 + 动作」，把复杂部分留给上游项目。
2. **BOM 要留余量**：同类项目翻车大多不是算法，而是电源、公差、连接器。清单里固定留 15% 备件费，电源按峰值 90% 设计。
3. **先本地后云端**：默认离线可用，联网只能是增强。这样项目不会因为某个 API 停服而报废。
4. **验证要能自动化**：能用 pytest / 几何计算 / 电源预算验证的，绝不写成「目测正常」。硬件体验项必须人工记录，且写清谁、何时、怎么测。
5. **价格锚点**：桌面陪伴入门档材料 ¥200-300 可以做出完整体验；超过 ¥800 就必须有明确的能力跃迁，否则用户不如买成品。

## 对设计的直接影响

- 电源用 5V/3A 适配器 + 1000uF 电容，不做电池。
- 语音识别放主机，固件只做 I2S 搬运，避免在 MCU 上堆模型。
- must 需求压到 6 条，每条都要有证据；其余进 should/nice。
- 装配文档必须有检查点，不能只写「装好即可」。

## 还没搞清楚的

- GC9A01 不同批次的排线方向不一致，头壳卡扣需要按实物微调。
- 低成本 ToF 在强光下的漂移范围没有实测数据，先按保守阈值 800 mm 设计。
- MG90S 的实际堵转电流随批次差异较大，电源预算按 550 mA/个估算，实测后回来改 robot.yaml。
