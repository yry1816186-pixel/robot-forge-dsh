# 08 故障排查

排查顺序永远是：先看现象 → 再定位是电、是机械、还是软件 → 一次只改一个变量。

## 快速定位

| 症状 | 最可能的原因 | 先做什么 |
|---|---|---|
| 插电完全没反应 | 适配器、USB 线、开发板供电 | 换线换头，量 5V |
| 屏幕白屏 | 背光、复位、SPI 接线 | 查 BL/RST，重烧固件 |
| 屏幕花屏 | 排线接触不良、SPI 太快 | 重插排线，降低 SPI 频率 |
| 舵机不动 | 电源不足、信号线错、限位 | 量舵机电压，查 GPIO15/16 |
| 舵机抖动 | 共地不良、电源纹波 | 加 1000uF，检查地线 |
| 一动就重启 | 电源掉压 | 换 5V/3A，加粗线 |
| 叫名字没反应 | 主机软件没开、麦克风没接 | 看串口日志，先跑模拟模式 |
| 有反应但不说话 | 喇叭、TTS、音量 | 查功放接线与 VOL 设置 |
| 触摸没反应 | TTP223 模式脚、共地 | 量输出脚电平 |
| 测距一直是 8190 | I2C 没通、地址错 | 扫描 I2C 地址 0x29 |
| 灯环只亮第一颗 | 数据线太长、电阻 | 缩短线，串 330Ω |
| 串口打不开 | 被监视器占用、驱动 | 关掉 pio monitor，重装驱动 |

## 按模块排查

### 电源

1. 万用表量适配器空载电压，应在 5.0-5.2V。
2. 接上负载再量，低于 4.7V 说明带不动，换更大电流的适配器。
3. 量开发板 3.3V 脚，应为 3.25-3.35V。
4. 摸舵机外壳，明显发烫说明堵转或电源异常。

### 屏幕

1. 白屏但背光亮：查 RST 是否接对，SPI 模式是否 0。
2. 完全不亮：查 BL 引脚是否有 3.3V。
3. 花屏：把 SPI 频率降到 20 MHz 试。
4. 颜色反了：改 face.cpp 里的颜色配置，不要改接线。

### 舵机

1. 断开舵机，只上电，确认开发板不重启。
2. 单独接一个舵机，发 POSE 0 0，看是否动。
3. 两个都动但方向反：在 config.h 里反转对应轴，不要拆舵机。
4. 有嗡嗡声但不转：可能扫齿，换舵机。

### 音频

1. 先确认串口能收到 MIC 数据，没有数据就先查 I2S 接线。
2. 有数据但没声音：查功放 SD 脚是否拉高、喇叭是否 4Ω。
3. 声音断续：查主机 CPU 占用与串口缓冲。
4. 啸叫：麦克风远离喇叭，降低音量。

### 软件

1. 先跑模拟模式，确认软件本身没问题。
2. 模拟模式正常、真机不正常，问题在串口或硬件。
3. 串口能连但没数据，检查波特率是否 921600。
4. 报错看不懂，把完整日志和 forge/evidence.jsonl 一起发到 issue。

## 什么时候该停

- 冒烟、焦味、发烫到烫手：立即断电，不要再试。
- 同一个问题改三次仍不好：停下来，记录你改过什么，从干净状态重来。
- 不确定电压或极性：先问，不要赌。

## 收集信息

发 issue 时附上：

~~~bash
python tools/forge.py status
python tools/forge.py verify
~~~

以及串口日志的前 30 行和报错行。有了这些，定位会快很多。
