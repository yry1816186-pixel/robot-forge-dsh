# 04 固件说明

固件负责三件事：把音频搬进搬出、执行表情与动作、上报触摸与测距事件。它不做语音识别，也不做大模型推理。

## 环境

需要 PlatformIO Core（命令行版即可），以及一块 ESP32-S3 开发板。

~~~bash
python -m pip install platformio
pio --version
~~~

推荐版本：

| 组件 | 版本 | 说明 |
|---|---|---|
| PlatformIO Core | 6.x | 命令行工具 |
| platform-espressif32 | 6.9.0 | 固定在 platformio.ini，升级前先看发布说明 |
| Arduino core | 2.0.x | 随平台安装，不需要单独装 |
| LovyanGFX | 1.1.x | 屏幕驱动 |
| FastLED | 3.6.x | 灯环 |
| Adafruit VL53L0X | 1.2.x | 测距 |

首次编译会下载依赖，国内网络可能需要设置代理或使用镜像。

## 烧录

~~~bash
cd firmware
pio run -e esp32-s3
pio run -e esp32-s3 -t upload
pio device monitor -b 921600
~~~

看到类似下面的日志就算启动成功：

~~~text
[forge] boot v0.1.0
[forge] display ok
[forge] servo home pan=90 tilt=20
[forge] ready
~~~

如果卡在 servo home，立刻断电：可能是舵机方向装反或机械卡死。先手动转一下头部，再上电。

## 代码结构

~~~text
firmware/
├── platformio.ini        环境与依赖版本
├── include/config.h      引脚、限位、阈值（与 robot.yaml 对应）
├── lib/protocol/        纯 C++ 文本协议解析（native 可单测）
├── src/
│   ├── main.cpp          启动、主循环、串口协议分发
│   ├── motion.h/.cpp     舵机限速、限位、堵转超时
│   ├── face.h/.cpp       眼睛与表情
│   └── sensors.h/.cpp    触摸、测距、麦克风
└── test/test_protocol.cpp 协议与限位单测（native）
~~~

## 协议

固件与主机之间是单行文本，换行结尾，波特率 921600：

| 方向 | 消息 | 含义 |
|---|---|---|
| 主机→固件 | EMO happy | 切换表情：idle/happy/curious/sleepy/alert |
| 主机→固件 | POSE 30 -10 | 左右 30 度、俯仰 -10 度（会限位与限速） |
| 主机→固件 | LED 255 128 0 | 灯环颜色 |
| 主机→固件 | MIC ON / MIC OFF | 开始/停止麦克风采集 |
| 主机→固件 | VOL 60 | 音量 0-100 |
| 固件→主机 | TOUCH head | 触摸事件 |
| 固件→主机 | DIST 620 | 测距毫米值 |
| 固件→主机 | LEVEL 42 | 麦克风能量 0-100，仅在 MIC ON 时上报 |
| 固件→主机 | READY | 启动完成 |
| 固件→主机 | ERR stall | 堵转保护触发 |

非法消息一律忽略并回 ERR syntax，不会让固件进入未知状态。

## 单测

~~~bash
pio test -e native
~~~

原生测试覆盖：协议解析、非法输入拒绝、角度限位、堵转超时计算。它不需要开发板，CI 里也能跑。

## 与 robot.yaml 的关系

引脚定义在固件的 include/config.h 里，但**源头是 forge/robot.yaml**。改硬件接线时先改 robot.yaml，再同步 config.h，最后跑 check；检查会发现文档与配置不一致。

## 升级

- 改固件版本号时同步改 forge/robot.yaml 的 project.version 与 CHANGELOG。
- 没有做 OTA。桌面设备插 USB 升级更简单，也避免半包升级导致变砖。
- 升级前先记录当前版本与验证状态，升级后重新跑 verify。
