# Robot Forge v2.0.2 发布报告

- 版本：2.0.2
- 日期：2026-11-11
- 状态：补丁发布（Patch Release），修复公开 CI 的环境可移植性
- 适用宿主：DeepSeek Harness（DSH）0.2.x
- 许可证：MIT

## 1. 摘要

v2.0.2 不改变任何生成项目的契约、12 个工具、评分规则、参考手册或蓝本。它只修复插件自身在**干净 CI 环境**中的两个可移植性缺陷：

1. Windows runner 的 cp1252 控制台无法打印校验器的中文状态行，导致 6 个 Windows job 在 Validate bundle 步骤直接抛 `UnicodeEncodeError`。
2. Ubuntu runner 先跑 pytest 生成 `.pytest_cache`，随后 Blueprint selftest 的 P071 缓存卫生检查把它判为错误，导致 6 个 Ubuntu job 在 selftest 步骤失败。

修复后，校验器在 cp1252 控制台也能输出 UTF-8 诊断；CI 的所有步骤都禁用字节码与 pytest 缓存；本地 `npm test` 也不会再污染发布树。

## 2. 触发问题

GitHub Actions run [43011968820](https://github.com/yry1816186-pixel/robot-forge-dsh/actions/runs/43011968820) 的 12 个 job（Ubuntu/Windows × Python 3.11/3.12/3.13 × Node 22/24）全部失败。

### 2.1 Windows：cp1252 控制台无法编码中文

失败步骤：`Validate bundle`。日志原文（节选）：

```text
File "D:\a\robot-forge-dsh\robot-forge-dsh\skills\robot-forge\scripts\forgekit\validate.py", line 356, in main
    print("robot-forge DSH bundle 校验：%s" % root)
UnicodeEncodeError: 'charmap' codec can't encode characters in position 23-25:
character maps to <undefined>
```

Windows GitHub runner 的控制台编码是 cp1252，校验器启动后第一行中文诊断就失败。开发机使用 UTF-8 控制台，因此本地无法复现。

### 2.2 Ubuntu：pytest 缓存触发 P071

失败步骤：`Blueprint selftest`。日志原文（节选）：

```text
[ERROR] P071 存在缓存目录 /home/runner/work/robot-forge-dsh/robot-forge-dsh/.pytest_cache
```

CI 的顺序是 Validate → pytest → Host test → selftest。pytest 在仓库根目录生成 `.pytest_cache`，而 selftest 的发布卫生检查 P071 要求仓库中不存在缓存目录。两个步骤单独看都正确，组合起来却互相拆台。

## 3. 修复内容

| 文件 | 改动 | 作用 |
|---|---|---|
| `skills/robot-forge/scripts/forgekit/validate.py` | 新增 `_force_utf8_stdio()`，在 `main()` 入口把 stdout/stderr 重配置为 UTF-8（`errors="replace"`） | cp1252 / cp936 控制台不再因中文诊断崩溃；GitHub 日志仍是可读 UTF-8 |
| `.github/workflows/ci.yml` | job 级 `env` 增加 `PYTHONDONTWRITEBYTECODE=1`、`PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1`；pytest 加 `-p no:cacheprovider` | 所有矩阵步骤编码一致；pytest 不再生成 `.pytest_cache`；不生成 `__pycache__` |
| `package.json` | `test` / `test:engine` 加 `-p no:cacheprovider`；版本锁步到 2.0.2 | 本地按文档执行也不会制造 P071 假红 |
| `SKILL.md` / `forgekit/__init__.py` / `CHANGELOG.md` | 版本锁步到 2.0.2 | 满足 P047 版本一致性 |
| `README.md` / `docs/acceptance.md` | 安装 URL 与验收版本更新到 2.0.2 | 用户按文档安装到正确版本 |

没有修改：生成项目模板、`robot.yaml` 契约、`verify.yaml` 语义、CST/DSN 规则、六维评分、发布门、12 个工具 schema、11 篇 references。

- 六维评分、CST-01…14、DSN-01…11、release/beta/blocked 判定不变；
- 11 篇 references 与 12 个形态配方不变；
- 无需迁移脚本，无需重新生成项目。

## 6. 安装与升级

从 2.0.1 升级无需迁移项目。把 profile 的依赖指向新 tarball、重新安装并重启 Harness 即可：

```bash
dsh plugin --profile desktop add "https://github.com/yry1816186-pixel/robot-forge-dsh/releases/download/v2.0.2/robot-forge-dsh-2.0.2.tgz"
```

仍需把 `robot-forge-dsh` 加入 profile `package.json` 的 `dsh.profile.bundles`，否则 DSH 不会加载 patch。Web 安装方式不变。
